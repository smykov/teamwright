# /teamwright:status

Read-only. Arguments: `$ARGUMENTS` (`--gate` also runs the gate).

1. **Config**: `.teamwright/config.yml` — `mode`, `process_version`, `tools`, areas with their commands and `runner` (`host`, or `docker` + `image`), `gate_command`. For a docker area, compare its `image` with the image the CI job for that area uses: a mismatch is a finding (local results may differ from CI). Missing → say teamwright is not installed and suggest `/teamwright:adopt` or `/teamwright:init`; stop.
1a. **Process settings**: `settings` from `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/tw-next.py" --json` — review blocking threshold, pass size and per-priority caps, autonomy start/continue, stages (batch, min, max_wait_hours), models per stage, `router.select`; mark each as set or default (`explicit`), and next to it the recommended value from `recommended` in the same JSON. A key left at its default whose recommended value differs (e.g. no `models.<stage>` while `opus`/`sonnet` is recommended) is one line under the table: "recommended: <key> <value> — `/teamwright:settings <key> <value>`". Changing them: `/teamwright:settings`.
2. **Install drift**: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/tw-install.py" plan --json` — kit updates available, tool blocks out of date, `kept-local` files, conflicts, unresolved placeholders. Nothing to do → "in sync". A conflict on a file the owner already merged by hand → suggest `tw-install.py apply --accept <path>` so it stops reappearing.
3. **Hooks and MCP**: `bash scripts/install-hooks.sh --check`; the teamwright hook commands present in `.claude/settings.json`; `.mcp.json` servers vs the chosen tools, and whether each chosen MCP server is actually connected in this session (its tools are available) — configured but not connected → "restart Claude Code and approve <name>".
3a. **Context tool really works**: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/tw-context.py" --json` — the languages the tool indexes against each area's languages (an area whose language is not indexed is read with grep and whole files: name it, and for a `runner: docker` area say the language server is likely missing on the host), and the share of code reading that went through the tool, per role, over the last sessions. Report every `findings` line; a configured tool nobody uses is a finding, not a detail.
4. **Tasks**: count the task records `docs/tasks/<ID>.md` (any id the hooks accept, `TEAMWRIGHT_TASK_ID_RE`; not the `_*.md` templates) by `status:` in the front matter; list `BLOCKED`, `VERIFY_FAIL`, `NEEDS_REVIEW`; the active task from `.teamwright/current-task`; a `TEAMWRIGHT_PAUSE` file means pushes are paused.
5. **Next action**: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/tw-next.py" --json` — show `action`, `task`, `reason`, `stage` and `command`, the tasks waiting per stage (`stages`, held ones with why), the first alternatives and any `warnings` (a `stage:` field the evidence contradicts among them); `/teamwright:flow` executes it, `/teamwright:router` one stage of it.
6. **Gate** (only with `--gate`, or after asking): `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/tw-install.py" check-commands` — every configured command through its runner, pass / fail / not runnable per area, and whether tracked files changed.
7. **Ready to enforce?** In `gate-first`: yes when the gate is green and no first-sprint gate task is open → suggest `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/tw-install.py" enforce` (the owner runs or approves it).

Output: one short table (config · settings · runners · context tool · drift · hooks · tasks · router decision · gate · next step). Metrics are separate: `python3 scripts/metrics/teamwright-metrics`.
